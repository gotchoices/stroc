# Stroc Workflow (Change & Delivery)

## Change/Iteration Process

When we encounter problems or modify features:
1. **Re-evaluate the specs** (Specification.md, STATUS.md, Implementation.md).
2. **Propose spec changes** to the user; update specs only after agreement.
3. **Re-implement** according to the updated specs.
4. **Define and share test criteria** for the change.
5. **User tests** and provides feedback.
6. **Commit** (user performed) at each milestone.

## Development Flow (per iteration)
- Identify the change/issue.
- Confirm spec impact and update docs if needed (with user approval).
- Implement in code.
- Run/check agreed tests; provide test steps to user.
- User validation.
- Commit the milestone.

## Artifacts to Keep in Sync
- `docs/Specification.md`
- `docs/STATUS.md`
- `docs/Implementation.md`
- `docs/Workflow.md` (this document)
